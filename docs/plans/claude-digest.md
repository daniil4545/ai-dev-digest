# Спека: дайджест через Claude Code

Статус: agreed
Каноны: AGENTS.md (поток, модель NewsItem, приоритеты отбора), код `src/` на коммите 20ce05a

## 1. Цель и границы

- Цель: дайджест AI и dev-новостей для владельца, по которому он пишет посты в свой Telegram-канал. Разбор новостей делает Claude Code вместо локальной модели
- Готовый результат: `/digest` в сессии Claude Code в этом репозитории создаёт `digests/YYYY-MM-DD.md`: до 10 разборов по оригиналу и короткий список; новости из прошлых дайджестов не повторяются
- Делаем:
  - сборщик остаётся; CLI `collect` и `mark`; проектный скилл `digest` (раздел 5)
  - источники по [claude-digest-sources.md](claude-digest-sources.md)
  - удалить Telegram-бота, APScheduler, Ollama-скоринг, форматтер, их тесты и настройки
  - обновить документы и зависимости (этап 2 и раздел 5)
- Не делаем:
  - посты в канал и мнения владельца, публикацию куда-либо
  - расписание и запуск без человека
  - поиск новых источников (отдельная задача)
  - правку резюме в career (строку про Ollama-скоринг владелец правит сам)

## 2. Архитектура

Поток: `/digest`, `collect`, отбор, WebFetch оригиналов, файл, `mark`.

| Блок | Ответственность | Взаимодействует с |
|---|---|---|
| `src/collect.py` | сбор, нормализация, фильтр по возрасту, изоляция сбоев | RSS, HN API, GitHub Trending |
| `src/storage.py` | таблица `sent_links`: какие ссылки уже были в дайджесте | SQLite `data/digest.db` |
| `src/main.py` | CLI `collect` и `mark` | collect, storage, stdout |
| скилл `digest` | отбор, чтение оригиналов, разбор на русском, файл, вызов `mark` | CLI, WebFetch, файловая система |

- Инициатор: владелец (`/digest`); источник истины о прошлых дайджестах: `sent_links`
- Владелец состояния: `storage.py`; side effects: только файл в `digests/`, наружу ничего

## 3. Сценарии

| Сценарий | Начальное состояние и шаги | Результат, состояние, side effects |
|---|---|---|
| Happy path | `/digest`: `collect` отдаёт кандидатов за 72 часа без ссылок из `sent_links`; скилл выбирает до 10 по приоритетам, читает оригиналы, пишет файл, вызывает `mark` | `digests/2026-09-30.md`; ссылки из файла в `sent_links` |
| Повтор в тот же день | второй `/digest` | `collect` не отдаёт ссылки из первого дайджеста; файл `2026-09-30-2.md`, первый не перезаписывается |
| Не выбранные новости | новость собрана, но не попала в дайджест | в `sent_links` не пишется, может попасть в следующий дайджест, пока моложе 72 часов |
| Сбой источника | источник недоступен или отдаёт мусор | источник пропущен, предупреждение в stderr, остальные собраны; скилл называет в чате источники со сбоем |
| Оригинал не открылся | WebFetch: 403 (так отвечает openai.com), paywall, пустая страница | разбор по пересказу той же новости из кандидатов (Habr), нет пересказа - по summary; пометка в разборе |
| Нет кандидатов | все источники упали или новых новостей нет | файл не создаётся, `mark` не вызывается, скилл говорит об этом в чате |
| Сессия прервалась до `mark` | ссылки не отмечены | следующий запуск покажет те же новости; допустимо |
| Сильных меньше 10 | тихий день | разборов столько, сколько подходит, без добивки |

## 4. Данные и состояния

| Сущность | Изменение | Владелец | Ключ или инвариант |
|---|---|---|---|
| `sent_links` | без изменений схемы, смысл: «ссылка была в дайджесте» | `storage.py` | `url UNIQUE`, `INSERT OR IGNORE` |
| `news_items`, `digest_runs` | не пишутся; в старой БД остаются | - | - |
| `NewsItem` | убрать `why_it_matters`, `action`; `score` - популярность в источнике (HN, GitHub), для RSS 0 | `models.py` | - |
| файл дайджеста | создаётся скиллом, не перезаписывается | скилл | имя `YYYY-MM-DD.md`, при занятом `YYYY-MM-DD-N.md` |

- Вход: ленты `sources.py`, окно `MAX_ITEM_HOURS` = 72; ссылка попадает в `sent_links` только через `mark`, повторный `mark` идемпотентен

## 5. Кодовая модель

```python
# src/main.py
DB_PATH = <корень проекта>/data/digest.db

def collect_candidates(storage: Storage, max_item_hours: int) -> list[NewsItem]
def mark_digest(storage: Storage, digest_path: Path) -> int
def main(argv: list[str] | None = None) -> int
```

- `collect_candidates`: `collect_all`, минус дубли по url внутри запуска, минус url из `sent_links`
- `mark_digest`: прочитать файл, найти все ссылки `https?://...` регуляркой, отметить каждую в `sent_links`. Выход: число ссылок; нет файла - код 1
- `main`: разбор аргументов через `argparse`; `collect` печатает JSON-массив `{title, url, source, published_at, summary, score}` в stdout, логи идут в stderr; `mark <файл>` печатает число отмеченных ссылок

Изменения в существующем:
- `storage.py`: остаются `mark_link_sent`, `was_link_sent`, `close`; `_create_tables` создаёт только `sent_links`
- `config.py`: `Config` из `max_item_hours` (по умолчанию 72); `DEBUG_SCOOP` удалить (служил быстрому прогону LLM)
- `sources.py`: список из [claude-digest-sources.md](claude-digest-sources.md); поле `category` удалить
- `collect.py`: удалить `fetch_reddit_hot`, тип `reddit_api`, `debug_scoop`; summary очищать от HTML (`BeautifulSoup.get_text`); url нормализовать до дедупа: без `utm_*` и хвостового `/` (OpenAI и HN дают одну статью с `/` и без, Habr добавляет `utm_*`); дата из `updated_parsed`, если нет `published_parsed` (в Atom бывает только `updated`, иначе запись всегда «сегодня»); в заголовках GitHub Trending схлопывать пробелы и переводы строк
- `.gitignore`: `digests/`
- удалить `llm.py`, `telegram.py`, `scheduler.py`, `digest.py` и их тесты; из `requirements.txt` убрать `python-telegram-bot`, `APScheduler`, `ollama`

Скилл `.claude/skills/digest/SKILL.md`:
1. `.venv/bin/python -m src.main collect`; кандидатов нет - сказать и закончить
2. Выбрать до 10 для разбора и до 10 для короткого списка по приоритетам (раздел из AGENTS.md переносится в скилл): вверх coding agents, developer tools, workflow automation, практические обновления, новые AI-инструменты; вниз общий хайп, маркетинг, crypto
3. Каждый из топа открыть через WebFetch; не открылся - пересказ той же новости среди кандидатов, потом summary
4. Записать файл по формату ниже; url копировать из JSON без изменений, иначе дедуп не сработает
5. `.venv/bin/python -m src.main mark <файл>`; в чат: путь к файлу, число новостей, источники со сбоем

Формат файла, язык разбора русский:

```markdown
# Дайджест 30.09.2026

## 1. <Заголовок по-русски>

<источник>, <дата> - <url>

**Что произошло.** 2-4 предложения по оригиналу.
**Почему это важно LLM-инженеру.** 1-3 предложения.
**Вопрос для поста.** Один вопрос, над которым стоит подумать.

## Коротко

- <заголовок по-русски>: одна строка. <url>
```

## 6. Этапы реализации

| Этап | Проверяемый результат | Зависимости | Границы | Проверка |
|---|---|---|---|---|
| 1. Сборщик и CLI | `collect` отдаёт JSON кандидатов, `mark` пишет ссылки; бот, LLM, планировщик удалены; источники обновлены | нет | без скилла | команда из раздела 7; живой `collect`: есть Habr и Reddit |
| 2. Скилл и документы | `/digest` создаёт файл дайджеста; README, AGENTS.md, TASKS.md, CHANGELOG, `.env.example` описывают новый поток | этап 1 | без поиска новых источников | прогон `/digest` сегодня и второй прогон |

Тесты этапа 1 (без сети, на фейковых сборщиках и временной SQLite):
- `collect` не отдаёт ссылки из `sent_links` и дубли внутри запуска
- круг `collect`, `mark`, `collect`: во втором ответе нет отмеченных ссылок
- `mark` находит ссылки в markdown-файле, без хвостовых `.,;)>`; повторный `mark` не падает; нет файла - код 1
- `fetch_rss` разбирает Atom (Reddit, YouTube) и берёт дату из `updated`; нормализация url; заголовок Trending без переводов строк

## 7. Критерий приёмки

- Команда: `.venv/bin/python -m pytest -q && .venv/bin/ruff check . && .venv/bin/ruff format --check .`. Пока она не зелёная, о готовности не сообщать
- Тестовый сценарий:
  - `/digest` сегодня создаёт `digests/2026-09-30.md` с разборами (до 10) по формату и коротким списком
  - второй `/digest` не повторяет ни одной ссылки из первого файла
  - `digests/` не попадает в `git status`
- Не автоматизируется: качество отбора и разбора оценивает владелец по первому дайджесту
- Не проверяем: стабильность Reddit RSS во времени; CI на GitHub до push
